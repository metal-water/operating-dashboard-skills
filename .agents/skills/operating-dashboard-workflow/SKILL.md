# 经营看板生成

用户通常只提供链接和少量自然语言变化。默认由你读取源表、形成字段映射及规范化报告，用户不需要填写 JSON/YAML。沿用随包提供的视觉模板，月份、字段与主体不要从历史样例硬编码。

## 工作流

1. 判断任务是新一期生成还是局部改版。局部改版读取用户选定基线，保留未要求改变的数据与交互；新一期不要把上期数值当成缺失数据的补充。路径从当前输入和工作目录解析。
2. 阅读 [source-mapping.md](references/source-mapping.md)；列出源文档、时间、预算版本及实际可访问的总表/分表。优先使用现成授权连接器或 API；浏览器读取时加载全部行列和嵌入表格。缺访问条件时只请求必要权限或文件，保留已完成的工作。
3. 依每店、每期原表建立完整多层表头与来源字段清单，记录隐藏行列、会计口径和字段血缘，再配对主副行。右侧远端对照列也在读取范围；不能按其他店列号或相似名字猜字段。参见 source-mapping 中的“完整字段与可见性”。
4. 阅读 [report-contract.md](references/report-contract.md)，生成本次 `report.json`。每个显示值都关联来源单元格；主值、副值和图标状态可有三个不同来源。数字 0、空值与读取失败分别保存。
5. 字体与框架按 [visual-profile.md](references/visual-profile.md) 和 `assets/defaults.json`，沿用 V41 商务渐变、双层四卡、双行与冻结交互。默认展示原表可见行列；一级没有全部字段按钮，二级全部字段同时展开已读取的隐藏行列。不可把原表可见的毛利、毛利2等字段自行精简。当次变化写入 display 或版本副本；只有用户明确要求长期更新时才改共享模板。
6. 新报告运行 `node scripts/build.cjs --input <report.json> --out <output-directory>`，路径以本 Skill 所在目录为基准解析。生成器自动版本化输出离线 HTML、证据报告和 `handoff.json`。已有 HTML 的增量改版也必须新建版本并保留证据记录。
7. 阅读 [acceptance.md](references/acceptance.md)，执行输入校验和浏览器验证。校验结构不等于已核对财务来源；明确记录未读、未映射、未审核字段及覆盖率。
8. 报告可打开的绝对路径、关键变化、实际验证结果、未解决事项。需要独立复核时给出 `handoff.json` 和新对话调用文本。仅在用户明确要求新建对话且宿主支持时创建，复核独立读取原始来源。

## 必须保持的边界

- 最新用户明确要求优先于历史版本和参考文档。一次性月度配置不自动成为通用规则。
- 使用同期间、同预算版本的权威来源快照；在线与 Excel 不按文件形式决定优先级。无法判定哪版正确时说明具体冲突。
- 公司/门店发布总数与项目分表可能属于不同责任口径，不强行用项目求和替代。相同游戏在研发和发行分表出现时不去重丢数或重复汇总。
- 不将 `实际 ÷ 达成率` 默认视为预算，不平均费毛比，不将所有 VS T2+10 都当百分比，不用负号或业务颜色单独推断所有达成状态。
- 核对必须包含来源字段的语义正确性；不能只比较自己生成的映射与自己生成的值。
- 主副行颜色分别跟随各自源图标；未读颜色保持未知。数字疑似缺位、缺负号或受图标遮挡时，核对公式栏/完整单元格值，保留可见文本与完整值证据，不按裁切截图改数字。
- 不把真实经营数据、文档链接、凭据或本机路径写进可分享模板。每次运行的证据保留在输出目录。
