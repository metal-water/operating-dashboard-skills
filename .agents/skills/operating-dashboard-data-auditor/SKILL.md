# 经营数据独立核对

接收 `handoff.json`，或看板路径与原始数据链接。默认只核对，报告位置和修复建议。修复需要用户提出；共享模板不随审计改变。

1. 验证 HTML、report.json 与交接 hash；相对路径以交接文件目录为根。核对的是指定版本而非目录中名称相似的文件。缺交接时读取 HTML 和原始来源，自行形成审计清单。
2. 从交接定位文档后，**独立重新读取原始表格和多级表头**。生产配置可提供检索线索，不能直接作为正确答案；先依据原表判定主体、时间、责任、单位和对照类型，再比较生产映射。优先核对交接的同版本快照，线上已变更则记录来源变更，不混用两期。
3. 从源表先建立独立字段清单，再全量枚举公司及门店四项 KPI、一级总表与展开项目、所有二级分表。逐店检查月度及累计主副行，不只检查用户点名的店。一级核验默认隐藏策略；二级打开全部字段检查已读取的隐藏行列；源表仍未读区域单列，不能把按钮称为全量读取。核对原表可见但未进入模型的字段、被误显的隐藏项目。
4. 主/副值与图标各自取证：一级累计下行为预算，二级对照按源表定义；费毛比差额不与完成率混淆。副行颜色也跟随自己的源图标。0、源空白、无对应列、未读、冲突分别记录。疑似少一位或少负号时读公式栏/完整单元格值，交叉核对截图和原文，不能将主值取绝对值来生成副值，也不能依据图标遮挡后的文本修正数字。总分表口径不同先解释，不强行凑平。
5. 阅读 [audit-contract.md](references/audit-contract.md)，形成独立 `expected.json`。每条有原始单元格、期次、单位、值和 mappingVerified。不要从 report.json 抄值作为期望；生成脚本不负责真实性背书。
6. 可用 `node scripts/compare.cjs --report <report.json> --expected <expected.json> --out <audit.json>` 做规范值比较。再打开实际 HTML 检查显示映射，不能只审数据模型。写出人工语义检查、DOM 显示检查与状态图标检查的覆盖范围。
7. 输出差异、来源位置、预期/实际、建议、无法确认项；分列字段映射、主值、副值、空白证据、隐藏行列、状态/图标、当次重读/既有快照和 DOM 覆盖率。排序后仍按原始行路径比对。结构比较仅证明提供证据范围内一致，不等于完整财务通过。核对阶段不修改看板、源表或 Skill；用户另外要求修复时才进入修复流程。

表源无读取权限时准确说明，能从已授权导出的同版本 Excel 继续则继续。不要让用户手填一份技术映射配置；只询问无法从材料确定的实际业务歧义。
